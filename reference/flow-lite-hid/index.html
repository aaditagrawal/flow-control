01 / INTERFACES

One cable,
three personalities.

The Flow Lite is a composite HID device. Key output, persistent configuration, and pointer-style controls travel through different collections—even though macOS presents them as one keyboard.

INTERFACE 01STANDARD HID

Keyboard collection

The familiar USB keyboard path. Firmware resolves a physical key through the active OS map and layer, then emits the resulting keyboard usage.

Usage page0x0001
Usage0x0006
Input8 bytes
Output1 byte
  • Standard keyboard usages and eight modifiers
  • Output changes after firmware mapping is applied
  • Input Monitoring protects raw access on macOS
Why this matters

A remapped key still looks like a normal keyboard key to every computer. No Flow Control process needs to stay running for persistent key assignments.

INTERFACE 02PERSISTENT CONTROL

Consumer + vendor

This shared interface carries media usages and the private configuration channel used to read or write maps, macros, lighting and device settings.

Primary0C:0001
VendorFF02:0002
Report ID0x08
Payload16 + 16B
  • Four 128-record keymap layers
  • 15 macro slots and lighting parameters
  • Battery, firmware, polling and locks
Transaction contract

Commands are serialized, checksummed, retried within bounds and every production write is immediately read back. Backups are taken before mutation.

INTERFACE 03RELATIVE INPUT

Pointer collection

A mouse-like path declared by the same keyboard. It can carry mouse buttons, relative X/Y movement, vertical wheel and horizontal pan.

Usage page0x0001
Usage0x0002
Wheel01:0038
AC Pan0C:0238
  • Five mouse-button bits are declared
  • Wheel and pan are signed relative values
  • Candidate route for the physical roller
Evidence caveat

The descriptor proves that the path exists. A live dial capture is still needed to distinguish wheel events from Consumer volume-up/down events.

06 / BOUNDARIES

Supported does not
mean “send anything.”

The original web mapper had a firmware-corruption history. Flow Control separates ordinary configuration from recovery-sensitive commands and generic features not proven on this exact CID/MID.

Safe, verified surface

Backed by exact encoding evidence and device readback.

  • Four 84-key maps and established action families
  • Shortcut chords and one-shot macro assignments
  • 15 macro slots with timed press/release events
  • Built-in white-light modes and five-level controls
  • Polling, OS mode, Fn lock, keyboard lock and off timer
  • Backups, scoped writes and immediate verification

Intentionally excluded

Unverified, destructive, variant-specific or unsupported by this hardware.

  • Firmware update, bootloader entry and recovery writes
  • Receiver pairing, factory reset and clear operations
  • Generic iOS, Android and Fn2 storage
  • Per-key RGB claims on white-backlight hardware
  • Custom-light writes and simulated frame streaming
  • Unverified repeat-until-release macro encoding
